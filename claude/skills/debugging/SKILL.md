# 障害調査・デバッグ

- 原因特定が先。原因が確定するまで修正案に進まない。アプリ側・インフラ側の両方の変更履歴を洗う
- ライブラリ・ランタイム・OS より先に自分の書いたコードを疑う。外部のバグと判断するのは自分のコードを調べ尽くしてから
- 同じ問題で仮説が3回外れたら、レイヤを1つ上げて疑う(ミドルウェア → アプリ → DB / ネットワーク → OS)
- 推測のまま設定値・コード値を確定させない。実機検証(CLIワンライナーをユーザーに提供して結果を貰う等)を挟む
- アプリコードの不具合は、修正の前に再現する自動テストを書く。そのテストが落ちることを確認してから修正に入る
- 症状が消えても原因が直ったとは限らない。2つの不具合が互いを打ち消している可能性を、該当箇所を読んで確かめる
